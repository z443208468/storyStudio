# 通用输入包生产执行能力：R5 既有 Atom 范围修订候选

**状态：待独立只读 Controller 审查的范围候选。** 本文件提出对现有 ATOM-04/05/06/07 的有限依赖补充；不修改活动主计划，不新增 Atom，不授权实施、Live 调用、费用预留、TS 恢复、迁移或默认入口切换。

## 依据与用户目标

项目所有者的最终验收目标是：应用接收写作输入包，完整保留其中的要求和材料，将材料交给正确岗位，按原 CNW 工作流生产、审查并导出故事。应用负责流程、内部合同、Run、身份和哈希；输入包负责本次作品的素材与要求。

ATOM-09 的精确候选 `8e5f787f0c863d9c507c6120d2fa354e613dd4e3` / Tree `82b5b27c6c5bbfc62de0fa200363c5e4f2aaeef3` 已获得 `ACCEPT_LIMITED_OFFLINE`，并于远端 `main` 快进推送及回读。该裁决只接受隔离虚构项目的完整离线模拟能力，不表示通用 Live 生产已完成。

源码审查确认，当前输入包执行器可以完成离线 Run、实际 CNW 调度和模拟导出；但生产授权入口仍拒绝新 V2 项目，包执行没有 Live 路由，新的项目级费用上下文也没有接入两条真实 Provider 输送路径。因此“缺少 Key”不是全部差距：通用应用所需的生产执行和授权/费用衔接代码尚未实现。

## 范围与顺序

在 R5 现有 Atom 中补充明确依赖，不改变公开 CNW 阶段或职责：

- **ATOM-04：**让现有输入包命令能表达并传递执行意图，保持一个可理解的应用入口；不把项目路径、合同、Run ID 或内容 SHA 要求转嫁给用户手工填写。
- **ATOM-05：**为新项目选择并显式传递实例绑定的费用上下文；保留已有全局 Provider 并发上限，不迁移、改写、清零或写入真实旧账本。
- **ATOM-06：**生产路由继续使用实际角色、读集、CNW 阶段、审稿、Refine、受影响 Re-review 与导出消费者；模拟与 Live 证据不能互换。
- **ATOM-07：**复用可信独立审查验证，但将其与单独的用户 Live/费用授权分开。保持 `provider_call_authorized=false` 的既有可信审查结果，不得改位或把工程 ACCEPT 当作生产授权。

该补充仍依 R5 原有 Atom 顺序执行，不以本候选追认任何历史 RETURN，也不改变 `CUTOVER_BLOCKED=true`。

## 限定实现边界

范围获批后，实施仍须形成单独的本地候选并接受精确 C/T 独立审查。拟议实现只补通用输入包到现有生产执行链的缺失衔接：

1. 在现有包准备/执行 CLI 中加入清晰的执行意图及参数传递。保留来源获取的 `--offline` 语义，不混淆“离线下载来源”和“模型执行模式”。
2. 为生产执行创建独立且绑定当前项目实例、合同、来源、Policy 和 Run 的尝试；不得把离线 Run 或 `MOCK_ONLY/SIMULATED` 收据改标成 Live。
3. 复用现有可信 Controller 验证接口，并增加窄的用户 Live/费用授权适配边界。必须验证适用项目实例、Run、合同、来源、Policy、有效期、Provider 与费用上下文。无部署信任、用户授权或费用上下文时保持 fail closed，并报告精确阻断原因。
4. 让两条真实 Provider 输送路径消费同一验证后的授权边界，并把实例绑定的费用上下文显式传给对应 slot/reserve/settle 操作。不得临时切换模块全局 `LEDGER/config` 来选择项目账本；并发执行不得发生跨项目串账。
5. 两个项目各自的费用上下文只用于隔离归属，不会为每个项目复制一份额外 Provider 并发额度；原有共同并发上限继续有效。
6. 继续调用既有 `execute_checked`、11 阶段 CNW 消费者、受限 Refine/Re-review、恢复和导出实现。原创续章必须引用合格的真实已接受前章；模拟 carry-forward 不得作为生产连续性。

不得新增签名平台、重做账本架构、改写 CNW 角色/阶段、放宽审核或自动晋升 Canon，也不得改造无关平台或入口。

## 限定验证与明确不证明的事项

实施验证使用 Writer 拥有的虚构临时项目和临时费用文件，不读真实密钥、不发网络请求、不 reserve/settle 真实费用、不触及 TS/J19 真实历史账本、不恢复 TS、不做私有数据迁移。测试必须覆盖：

- 缺失、过期、错配、重放的用户授权；错项目实例、Run、合同、来源或 Policy；不可信签收；伪造/重标模拟回执；模拟前章；权限撤销后的恢复及缓存重用。所有拒绝均发生在 Provider slot、费用预留和 HTTP 之前。
- 两个虚构项目具有不同费用上下文；互换上下文必须被拒绝，即使显示项目名、工作单元或 Run 标签相同。不得回退到旧 P2 campaign/ledger。
- 合法绑定在多阶段操作中可按授权规则继续；重复请求不重复记账；恢复和缓存消费重新验证当前授权及身份。
- 用户输入包实际走同一应用入口，并由真实阶段函数生成各自产物、角色消息和可追溯身份；只有最终模型/网络边界可用明确 `MOCK_ONLY/SIMULATED` 确定性替身。模拟不通过 Live 验收、正式晋升或文学质量验收。
- 原 V1/旧项目路径的历史合同、阶段身份和费用记录兼容保护不退化；真实旧数据及账本哈希保持不变。

这些验证最多证明生产授权检查、实例费用上下文选择和阶段消费者可达一个被阻断/模拟的模型边界。它们不证明真实部署信任已配置、真实 Provider 请求成功、付费结果有效、真实作品质量合格、TS 可恢复或可以迁移/切换数据。
