# StoryStudio 治理 P2：方法保留、实现可修、成果验收

## 1. 授权与唯一权威

最新用户要求高于旧包对其意图的错误转述。本版明确撤销 P1 的“第三方源码/配置/依赖/运行副本一字节不得改变”“原生不兼容直接永久停止”“每 Atom 再找用户批准”等规则。

用户目标与原作事实优先；原作者文档和源码提供方法及实现参考；本计划提供工程选择；证据记录发生了什么，不产生虚构授权。来源允许使用 `USER_REQUIREMENT / UPSTREAM_METHOD / BUG_FIX / ENGINEERING_CHOICE / PROJECT_ADAPTATION`，不再强迫每个命令参数都冒称上游要求。

## 2. 保留什么，修复什么

| 类别 | 保留的内容 | 可直接修复/适配的内容 |
|---|---|---|
| CNW | Canon 与草稿分离；Plot→Scene Card→Writing Brief→Prose；评审反馈进入 Revision；文件交接 | 填本项目人物、世界、语言、模板实例、输入输出路径；增加本项目知识边界；将流程做成薄调用入口 |
| NK | 输入事件/角色/视角，按实际原路由和模板生成对应结果；结果真实用于写作输入 | 模型、端点、凭据、SDK 的 Chat/JSON 协议、路径、schema 传输及错误处理 |
| CritiCS | 原有 persona→三类剧情批评→Inspector；按反馈改剧情；Image/Voice→Leader 的原职责与调用关系 | 语法、漏传正文、错误导入、依赖冲突、输出提取、供应商接入、项目语言/事实范围 |
| Canon | 原稿事实、时间/分支约束、各角色已知信息、已定结果 | 私有索引和适用于当前样本的事实包；新场景只能是新增候选，不能反写原稿 |

“原方法保留”不宣称与原论文模型、研究实验、评分快照或随机生成文本相同。产物应称“固定上游来源的项目适配版”，而不是“原版零修改”。

## 3. 单 Writer、独立 Controller

Writer 执行；Controller 只读全文、源码、差异、调用原件和作品，返回 ACCEPT/RETURN/EXTERNAL_INPUT_NEEDED。Controller 可以指定受影响环节、必要修复和工程参数选择，不能替用户扩大商业发布、改 Canon 核心设定、换非 Flash 生产供应商或无上限花费。

Controller 对问题必须指出“哪个目标受损、哪份证据、如何修”，不能只要求增加表格列。文档拼写或可逆机械错误直接退回当前修改，不创建新验收阶段。独立 agent 失联可重建并读取完整交接，身份变更如实记录；不得让 Writer 自己换个标签签收。

## 4. 普通故障处理

先留一份根因所需原件，再做最小修复，重跑失败步骤与受影响消费者。依赖/接口/上游 bug 属于工程工作，不再属于 B11 永久封锁。选错方案时换同方法的实现路径，不静默删除功能。

同一确定性实现/输入错误没有修复时不得反复请求/重跑；可恢复网络错误遵循技术规范中的有限重试例外。连续两轮 Controller 因同一根因退回，下一轮先查根因与对照源码，再改；这是防空转规则，不是“次数到了就算完成”。

与故障无依赖的源稿整理、另一工具修复、离线验证可继续；只有依赖确实满足并被接受的消费者才可开始。未完成不能冒称完成。

## 5. 必须暂停受影响动作的外部事件

真实 Key 缺失/失效、账户无余额、费用保护达到上限、唯一源稿确实不可获得、需要用户才能完成的系统权限、公开泄漏或真实数据损坏风险。报告具体缺项和已完成成果；能做的无依赖工作继续。不得用“规则矛盾”“缺一个表格字段”“上游有 bug”列作这种事件。

严禁：擅自公开原稿或密钥；破坏用户已有数据；伪造调用/签收；绕过供应商鉴权；悄用其他模型；在用户审首场前批量扩写。必要暂停不等于目标已经完成。

## 6. 版本与接续

`third_party/*` 保留固定参考。生产副本 `runtime/patched/*/<source+patch-id>` 允许有补丁，且只从上游快照与已记录补丁重建；不得把未经记录的 runtime 手改当正式版本。自有适配、补丁、依赖锁、启动入口入 Git。源码、补丁、依赖、输入和阶段输出身份共同决定复用资格。

不改写旧 I01 失败成成功；追加 P2 修复证据。历史 main 为空不是清空现有工作分支的理由。默认沿当前合法分支推进，不做 force-push、reset --hard、git clean、未经许可的 rebase 或覆盖预存 WIP。

## 7. 签收不自我递归

每阶段冻结实现/输入/证据清单的候选 C/T，Controller 审核原件并接受；Writer 正常推送并回读同一 C/T，Controller 核对一致。其消息就是本阶段签收，无须再请用户批准。

签收消息引用被审 C/T；Writer 在随后状态记录提交中逐字或忠实转录消息及身份。状态记录不用“包含自身 commit 的 commit”，也不为只追加签收指针重跑产品测试。下一阶段开工前要能查到真实 Controller 消息及相应 C/T，而不是仅看 Writer 写的 ACCEPT 字样。

业务树有更改则重验受影响功能；只更新状态索引不重跑生成。私有产物不在 Git tree 中，因此签收同时绑定私有产物 SHA256 清单。若平台无法提供独立 agent 原消息 ID，保存原消息文本、时间、agent 身份和消息摘要，诚实标识来源，不捏造 ID。

## 8. 私有数据与费用

`inputs/private/`、`workspace/`、`runtime/`、`runs/`、`deliverables/`、`.env*`、密钥文件均忽略；可提交无值的 `.env.example`。仅向获授权 DeepSeek 发本场必要输入，不将整包材料送给额外服务；默认只监听 127.0.0.1。

费用/重试默认值详见技术规范：它们是本版保守工程选择，不是假称用户过去设过的限制，不是文学字数约束。真实 usage、价格快照估算和账户实际账单分开。无 usage 不是费用为零。

## 9. 最终验收

`DEPLOYED`、`WORKFLOW_METHOD_REVIEWED`、`LIVE_CHAIN_VERIFIED`、`ONE_SCENE_DELIVERED`、`READY_FOR_USER_REVIEW`、`USER_CREATIVE_ACCEPTED` 分开记录。不能用工程通过替代最后一项。即使用户主观尚未审阅，也必须把完整可读成果和复用入口交付出来，不停在文档或环境阶段。
